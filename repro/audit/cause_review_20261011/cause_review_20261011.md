# 독립 검토: VisRef 효과(VisRef−TSR)가 재현되지 않는 원인 (2026-10-11)

검토자: 독립 서브에이전트(Fable 5.1). 모델 실행 없음(네트워크 제한). 근거는 (i) 코드 `repro/visref/*.py`, `repro/run.py`, (ii) 논문 `VisRef_plain.txt`(이하 P:줄), (iii) 원자료 `repro/llm/final/merged.jsonl`(3,000행), `repro/llm/fill/merged.jsonl`(994행), `hidden_rank_check.json`을 직접 계산한 값이다. 계산 스크립트는 같은 폴더의 `analyze_cause.py`(→ `analyze_cause.json`), `extra_calcs.py`(→ `extra_calcs.json`). 이전 검토(10-10 주입 경로, 10-10 설계, 10-11 fill)와 주 세션 결론은 참고만 했고 수치는 모두 다시 계산했다. 확인하지 못한 것은 "미확인"으로 표시한다.

## 0. 한 줄 결론

사용자 가설("이미지 토큰을 뽑는 방법이 잘못돼서 효과가 안 난다")은 **구현 버그로는 배제**, **해석 차이로는 일부 열려 있음(Z 표현층·채움 방식)**, 그러나 원자료는 **구조적 한계(이 1B 파이프라인에서는 어떤 시각 토큰을 넣어도 답이 바뀌지 않는 구간이 대부분)**를 더 강하게 가리킨다. 가장 정보가 큰 다음 실험은 "선택 없이 시각 토큰 전부(|V|개)를 재주입하는 오라클"이다 — 이것이 TSR을 못 넘으면 선택 방법은 원인이 될 수 없고, 넘으면 선택이 병목임이 확정되어 hidden-state Z 변형으로 넘어갈 근거가 생긴다.

## 3. 사용자 가설 직접 판정: "이미지 토큰을 뽑는 방법이 잘못됐다"

### 3-1. 구현 버그인가 → 아니다 (배제)
- V: `extract_feature` 출력을 `reshape(-1, hidden)`한 행이 프롬프트의 `<IMG_CONTEXT>` 위치(`emb[sel] = vis`)와 DPP 입력, 재주입(`self.vis[sel]`, `methods.py:197`)에 **같은 객체**로 쓰인다. 썸네일 타일 포함(`model.py:77`, 공식 `use_thumbnail=True`). 이보다 다른 "추출"은 재주입 자체를 불가능하게 하므로 대안이 없다.
- 선택: `dpp.py` 재귀는 Chen `dpp.py` L19-31과 같고(정지 조건은 상대 1e-9 vs 절대 1e-10), 결과 인덱스 `sorted(sel)`이 `vis`의 행을 고른다. 2,261단계 모두 n_inject = min(m, n_unique_z, rank_V)로 rank 경계가 정확히 재현된다(`analyze_cause.json` injection).
- Z: `partial`에는 생성 토큰만 쌓이고 종료 토큰·`Wait`·구분자는 Z에 들어가지 않는다(`methods.py:174-187`).
- 정오 패턴도 버그 징후가 없다: TSR k=1 730문항의 ST 대비 답 변경 16건(fp16 잡음 기준선)과 비교해 VisRef k=1 713문항 38건, 방향 14:12.

### 3-2. 해석 차이인가 → 일부 그렇다 (중간), 그러나 검증된 것은 아니다
- 논문 문구 "\|V_k\|=m"(P:534-536, 577-581)과 Fig. 4(b)(P:794-795)는 저자 선택이 20%→30%에서 달라졌음을 시사하므로, 저자 구현에서는 커널 rank가 ≥0.3\|V\|였거나(은닉 상태 Z) rank 뒤를 무작위가 아닌 방식(관련성)으로 채웠어야 한다. 우리는 입력 임베딩 Z + rank 정지라서 이 구간이 통째로 없다. 이것이 "선택 방법이 논문과 다를 수 있다"는 가설의 실체다.
- 그러나 (a) fill(εI → m개)은 null이고, (b) \|V\|=256 문항(196개)은 채움 없이 85% 단계가 m에 도달하는데 VisRef−TSR −1.0(−4.6~+2.6)이며, (c) 은닉 Z도 hidden_rank_check상 앞 약 30–110개 뒤는 다양성 정보가 없는 꼬리다. 남은 미검증 요인은 "머리 약 30–110개의 내용이 입력 임베딩 Z와 은닉 Z에서 다르다"와 "관련성 순 꼬리"뿐이다.

### 3-3. 구조적 한계인가 → 그렇다 (높음)
- 자연 종료 334문항: 어떤 변형(rank·fill)이든 TSR과 정오가 사실상 같다(rank 0:2, fill 4:6). 1B는 `</think>`로 닫은 뒤 그 앞에 붙은 시각 토큰(76~998개)으로 답을 바꾸지 않는다.
- 절단 단계에서는 주입이 뒤의 생각을 바꾸기는 한다(이어가기 첫 400자에 image/figure/look 언급 VisRef 237/1,261 vs TSR 132/1,116; "Let me list all objects again" 류 시작 53건). 그러나 둘 다 이어간 248문항에서 VisRef−TSR −0.4(25:26). 즉 모델은 묶음을 인지하지만 정답률은 변하지 않는다.
- 따라서 "선택을 고치면 +3.5가 나온다"가 성립하려면, 더 좋은 토큰이 (i) 절단 지점 뒤 생각의 **정확도**를 바꾸거나 (ii) 닫힌 생각 뒤 답을 바꿔야 한다. (ii)는 현 자료에서 0에 가깝고, (i)는 검증되지 않았다 — 이것이 §5 오라클이 겨누는 지점이다.

## 5. 제안 실험

### 실험 1 (권고, 먼저): 선택 없는 오라클 — 시각 토큰 전부 재주입 (`visref_all`)
- **가설**: "선택 방법이 원인"이면, 선택이 고를 수 있는 최선의 부분집합을 포함하는 전체 V를 같은 위치·형식으로 넣었을 때 TSR을 넘어야 한다(논문도 전부 주입을 비용 문제로만 배제, P:300-301, 381-386). 넘지 못하면 선택 방법은 원인이 될 수 없다.
- **바꾸는 한 가지**: `select_tokens` 대신 `sel = range(|V|)`(`methods.py:196` 한 줄). 형식(태그 없음)·위치·정지 규칙·시드·채점 모두 b_main과 동일. `max_context`만 40,960 → 49,152(b_main에서는 최대 문맥 15,666으로 한 번도 묶이지 않았고, 전부 주입 시 31문항이 40,960을 넘어 'budget' 정지로 k가 바뀌는 것을 막기 위한 운영 변경; 49,152 초과 0문항). T4 메모리: 49k 토큰 KV ≈ 5.4GB/행(28층·KV 헤드 8·128·fp16 — 모델 config 기준 추정, 미확인).
- **표본·짝**: b_main 셔플 순서(`ids.json`, seed 0)에서 **b_main ST 첫 단계가 cap인 문항**(641)의 앞부분 n개. 첫 단계 종료 방식은 처치 전 변수이고, close층은 어떤 변형이든 정오가 동일(0:2, 4:6)해 정보가 0이며 eos층(25)은 빈 생각에 대량 주입이 해로움(fill −36%p)이 이미 보여 별도 보고. 같은 pid·같은 시드(CRN)로 b_main TSR·VisRef와 짝 비교. 층 변수는 b_main ST 값 사용(fill처럼 1단계 재생성 일치율 보고, fill은 874/976).
- **비용(추정, 프리필 비례 모형 + fill 세션 11.3h 실측 기준)**: 전부 주입은 rank 대비 문맥 비용 1.75배(cap층 1.80배). cap 접두 100문항 ≈ 2.7h, 150 ≈ 4.6h, 300 ≈ 7.9h, 400 ≈ 10.0h, 641 ≈ 15.4h. 이번 주 3–4h면 100–130문항(파일럿 겸 시간 보정), 다음 주 쿼터로 400까지 확장. 이중 probe는 넣지 않음(비용).
- **검출력**(cap층 VisRef−TSR 불일치율 13.1% 가정; 전부 주입은 불일치율이 더 클 수 있어 MDE는 √(불일치율 비)만큼 커짐): n=100 SE 3.6%p(MDE80 10.1), 300 → 2.1(5.9), 400 → 1.8(5.1), 641 → 1.4(4.0). 논문 +3.5가 cap층에만 있다면 층 효과 ≈ 3.5/0.641 = **5.5%p**가 기준값.
- **사전등록 해석 규칙(초안)** — 주 비교 `all − TSR`(cap층), 보조 `all − VisRef(rank)`, 부트스트랩 95% CI + McNemar:
  - R1 CI 하한 > 0 → "시각 토큰 재주입은 이 파이프라인에서도 도움이 된다 → 선택이 병목일 수 있음" → 실험 2로.
  - R2 CI가 0을 포함하고 상한 < 5.5 → "전부 넣어도 논문 폭이 안 나옴 → 선택 방법은 원인 아님(구조적 한계)" — 단서: 전체의 70%가 관련 없는 토큰이라 주의 희석로 이득이 가려질 가능성은 남음(논문은 전부 주입을 해롭다고 쓰지 않았음).
  - R3 CI가 0과 5.5를 모두 포함 → 판정 불가, n 확장.
  - R4 CI 상한 < 0 → "태그 없는 대량 주입은 해롭다 → 형식이 지배" → 선택 질문은 이 형식으로는 답할 수 없음; `<img>…</img>` 감싸기 변형을 다음 후보로.
  - 보조 지표: k 분포, cap→이어감 비율, 답 안 `</think>` 재출력, af 비율, 생각 토큰. 100문항 파일럿을 본 뒤 규칙을 바꾸지 않는다(파일럿 행은 최종 n에 포함).

### 실험 2 (실험 1이 R1일 때만): 은닉 상태 Z (`visref_hidden`)
- **가설**: 저자 구현의 가장 그럴듯한 읽기(Fig. 4(b)와 "\|V_k\|=m"을 동시에 만족하는 유일한 Z)가 입력 임베딩 Z와 다른 머리를 고르고 m개까지 채운다 → 오라클 이득의 상당 부분을 회수한다.
- **바꾸는 한 가지**: Z = z_k 토큰의 최종 norm(또는 28층) 은닉 상태(단계 종료 후 ctx+z_k를 한 번 더 forward, `output_hidden_states`; +약 10% 비용). V·정지 규칙(1e-9)·형식 그대로 → hidden_rank_check상 n_inject ≈ min(m, T)(정지 규칙 선택 수 905–1,014 ≥ m). 비용 ≈ fill(rank의 1.2배) + forward.
- **표본·검출력**: 실험 1과 같은 cap 접두(짝 3중: TSR, rank, all). 규칙: `hidden − TSR` CI 하한 > 0이고 점추정이 `all − TSR`의 절반 이상 → "Z 표현이 원인"; `hidden ≈ rank`인데 `all > TSR` → "양·표현 모두 아님, 토큰 내용 외 요인(형식·주의)" → 추가 변형 설계; 둘 다 null이면 실험 1의 R2와 같은 결론.
- 대안(더 싼 2안): 관련성 순 채움(`.backup_79eef648ebd1/`의 `visref_raw`, Table 7 "Relevance-only" 대응). 은닉 Z보다 논문 충실도는 낮지만 구현이 이미 있다.

### 하지 않기를 권하는 것
- 4,096 상한 재실행(자연 종료만 늘어 이어가기가 더 줄어듦), Ghosal식 다중 표본 H(비용 대비 정지 결정 변화 작음, 10-11 기록과 같은 판단), close층 포함 1,000문항 전부 실행(close층 정보 0, 비용 8%만 절약되긴 함 — 비용보다 해석 단순화 목적).

## 6. 한계·미확인
- 모델 실행 불가 → 커널 L_ii의 실제 크기 미확인. Chen 코드의 절대 ε=1e-10은 커널 스케일이 크면 rank 뒤 잡음 픽을 계속 고를 수 있어, "인용 코드가 rank에서 멈춘다"는 전제도 스케일 의존(10-07 합성 실험: 잡음 픽 0–14개).

- 자연 실험(\|V\|별)은 이미지 크기와 문항 유형이 섞인 관측 비교다.
